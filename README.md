# products

## Git-flow
1. Создать ветку от dev
2. Сделать доработки в своей ветке
3. Оставить pull request на мерж в dev
4. Разрешено мержить PR только после аппрува мейнтенера

## Именование веток
Ветка должна содержать в своем названии:
1. Префикс, описывающий назначение ветки
2. Номер issue для решения которого создана
3. Название пакета, в который вносятся изменения
4. Краткое описание доработки

## Префиксы в ветках:
1. **feat** - от слова feature - означает добавление новой функциональности
2. **fix** - означает исправление функциональности/поведения и т.д.
3. **test** - добавление или правка тестов
4. **chore** - добавление тех долга
5. **release** - правки необходимые для релиза/исправления поведения на CI/CD

*Пример*: `feat/1-front-add-new-component`

## Именование коммитов
1. Префикс, описывающий назначение коммита
2. В скобках указывается субъект взаимодействия
3. Описание изменений

*Пример*: `feat(some-func.ts): change functions params`
